The guard checks that the session identifies an existing user and returns JSON with status **401** before executing the handler. Consequently, anonymous grade updates cannot mutate data, and anonymous downloads cannot reach filesystem handling. No role restriction is added to material downloads.

### Canonical path confinement

The download handler:

1. Rejects absolute input paths.
2. Resolves the materials root and requested target, including symlinks.
3. Uses `target.relative_to(root)` to require component-based containment—not an unsafe string-prefix comparison.
4. Rejects missing paths, invalid paths, symlink loops, and non-files with a generic **404**.
5. Passes only the validated, resolved target to the existing `send_file` call.

This preserves the three legitimate cases explicitly covered by the supplied tests: ordinary files, nested files, and `sub/../notes.txt`. It also addresses the tested parent traversal, encoded traversal, absolute paths, same-prefix sibling directory, and symlink escape. ## Assumptions and limitations

- **Filesystem race:** This is a resolve/check/serve patch, not an atomic filesystem sandbox. It assumes untrusted users cannot replace files or directory entries between validation and `send_file` opening the target. If they can, descriptor-relative traversal with no-follow controls and serving the already-opened file is needed.
- Authentication relies on session integrity. The application currently hard-codes `SECRET_KEY = "dev-secret-key"`; production must use a strong, externally supplied secret.
